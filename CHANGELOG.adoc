==== Added

* `docs/proposals/short-lived-signing-certificates.adoc` — replace the
  permanent `CLAUDE_SIGNING_KEY` with an offline SSH CA and an issuer
  (OpenBao) that grants each session a certificate valid for minutes.
  It includes measured git behaviour with certificates (expiry makes a
  signature untrusted but does not stop signing) and compares the design
  with gitsign, a TPM key, FROST and the status quo. Design only.
* `docs/proposals/environment-of-environments.adoc` — how the kit becomes
  the environment of environments: an environment manifest beside the
  toolchain manifest, one capability record, rendered projections, the
  agent-session leg, BoJ registration, and coverage of echidna's core
  backends; with measured reachability from one agent session and the
  experiments to run before building.
* `docs/proposals/awesome-estate-maths-proving.adoc` — the awesome lists to
  create in `stuff-of-awe` for maths, proving and solving, derived from
  echidna's prover roster, and the tools echidna itself lacks.
* `docs/proposals/boj-prover-solver-cartridges.adoc` — three BoJ cartridges
  (`provers-mcp`, `solvers-mcp`, `code-verifiers-mcp`) on the capability
  record seam, what the store's `proof-mcp` becomes, and where
  Quintessence, Apodeixis.jl, atoma and bactarin land.
* `tools/proof-toolchain/toolchain.kyaml` — HOL Light, HOL4, ACL2, Mizar
  and PVS as `exception:recorded` entries, with Poly/ML and SBCL as their
  bundled runtimes (E6, owner decision 2026-10-27; PVS added after review
  showed its SBCL source build is BSD-3-Clause): the kit now declares all
  twelve of echidna's core backends. Smoke fixtures and wrappers are under
  `tools/proof-toolchain/smoke/`, installed by `install-smoke.sh` and
  tested against stub provers by `tests/proof_smoke_wrappers_test.sh`.
* `tools/environments/` — `environments.kyaml` (environment classes with a
  `measured` block), `probe-reachability.sh` and `hosts.txt` (experiment
  X1: reachability probe, HEAD by default, one-byte GET with `--get`).
* `scripts/proof-check.sh`, called by every `proof-check-*` recipe, and
  `tests/proof_check_test.sh`. Agda runs with PROOF-POLICY §2.1's
  `--safe --without-K --cubical-compatible`. A missing checker is reported
  `UNAVAILABLE` and the run exits 3, never a pass. The escape-hatch scan
  reads code only, so comments and strings no longer trip it. Checkers run
  on a copy, so they write nothing into the tree.
* `verification/proofs/agda/bofj-kitt-proofs.agda-lib`, so Agda can find
  the standard library through its registered libraries. `AGDA_STDLIB`
  overrides this with an explicit path.
* A `verus` entry in `tools/proof-toolchain/toolchain.kyaml`. The owner
  ruling of 2026-11-07 made Verus a default Rust verifier beside Creusot
  (PROOF-POLICY §1.2).

==== Fixed

Findings from the last review of #98, which merged before they were
addressed:

* `build/setup.sh` — the Cargo fallback installs `just` into a named root
  and puts that root's `bin` on `PATH`, so a distro Cargo without
  `~/.cargo/bin` on `PATH` no longer fails setup after a successful install.
* `tools/environments/probe-reachability.sh` — `--get` caps a body the
  server sends despite the byte range (`range-ignored`); a non-GNU `ldd`
  (FreeBSD) no longer stops the probe. `tests/probe_reachability_test.sh`
  covers both.
* `tools/proof-toolchain/toolchain.kyaml` — HOL Light's OCaml switch is a
  locked runtime entry; Poly/ML takes the newest stable tag, since HOL4
  names no version; Mizar names the i386 distribution it actually ships
  (static binaries, needing IA32 emulation on the host).
* `tools/environments/` and the environment proposal — the measurement adds
  Cargo's real index and download hosts, which answer, so `cargo install`
  is no longer reported as blocked by the refused crates.io API.
* Proposals — PVS has a priority-1 owner (`awesome-hol`); X1 covers every
  probeable environment class; `DRIFT` fields and the checker's lock hash
  are named in the cartridge contracts.
* `Justfile` `container-init` renders the `VERSION` placeholder; the dogfood gate's
  summary counts the K9 files the hook validated, not every `*.k9` path.

Proof artefacts brought in line with PROOF-POLICY (metadatastician/standards
at `9bdf864`):

* `just proof-check-all` could never pass. Its escape-hatch scan matched the
  template's own "no postulate" and "NO Admitted" comments in all 8 proof
  files. No CI job ran it.
* The Agda recipe ran `agda --safe` without the §2.1 flags, and every recipe
  exited 0 when its prover was missing.
* `docs/status/PROOF-STATUS.adoc` now uses the §5 vocabulary with no
  percentage. It records the 2026-11-09 session results (Agda 2.6.3 and
  Coq 8.18 check their template files, ACL2 8.5 and HOL Light pass their
  smoke fixtures, and the rest are not run). It also lists the obligations
  the proposals name for other repositories.
* `docs/status/PROOF-NEEDS.adoc` withdraws the template's ABI and typing
  obligations, since this repository has no ABI, FFI or typed API. TP-2 had
  put API typing in Lean, but §1 puts it in Idris2. The prover guide
  recommended Lean for its Mathlib, which §2 forbids; it now summarises §1.
* `tools/proof-toolchain/DESIGN.adoc` states the §6 deviation records the
  installer must write for every entry installed other than through Guix or
  the container.
* The cartridge proposal now keeps the §5 status, the §2.2 correspondence
  state and the §8 grade as three separate fields. The cartridges never
  write a grade: Mathesis derives grades from their receipts. An Agda
  receipt also carries its library pin and import cone.
* Review of the new escape-hatch scan found three cases it missed or
  misreported, all fixed with regression tests:
  ** a Lean character literal such as `'"'` opened a phantom string that
     hid a later `sorry`;
  ** an Agda identifier containing `--` was read as a comment that hid a
     later `postulate`;
  ** `admit` was flagged in Agda, where it is an ordinary name. Patterns are
     now chosen per language.
* `scripts/proof-check.sh` also makes a relative `AGDA_STDLIB` absolute and
  copies a linked proof directory as its contents.
* `toolchain.kyaml` gives Verus's own Z3 a `verus-z3` entry. The deviation
  records are written by the bundle build that owns the lock, and the
  exemption from them follows the install route rather than the tool.
* `.github/workflows/main-estate-audit.yml` calls the audit under cicd-suite's
  new name, `hyperpolymath/proven-cicd-and-workflows`. Since the rename on
  2026-11-09 the old name failed at startup with zero jobs.

==== Changed

* `build/setup.sh` — when no system package provides `just`, setup runs
  `cargo install just --version 1.56.0 --locked` (the estate mise.lock pin,
  above the `just` >= 1.42 floor) instead of piping a remote installer to
  `bash`; covered by `tests/setup_install_test.sh`.
* `.github/hooks/validate-k9.sh` — skips the two YAML session bindings
  (`coordination.k9`, `session/custom-checks.k9`) by file identity and
  section markers rather than reporting them as malformed K9-SVC
  components; `container/deploy.k9.ncl` and
  `.machine_readable/svc/k9/methodology-guard.k9.ncl` gain the `K9!` magic
  line and a pedigree block. The lasting fix is to migrate those bindings to
  the k9-coordination grammar in `standards`.
* Descriptiles moved to `.machine_readable/descriptiles/`, the canonical
  location, from the retired `.machine_readable/6a2/`. The stale July copies
  of `STATE`, `META` and `ECOSYSTEM` at `.machine_readable/` are removed: the
  `6a2/` versions superseded them. Every workflow, recipe and document that
  named the old paths now names the new ones (Hypatia SD004 and SD024).
* `.github/workflows/main-estate-audit.yml` — now a thin caller of
  cicd-suite's reusable estate audit, pinned at a full SHA and recorded in
  `actions.lock` with the gate commits it reaches. The old file was a copy of
  the retired 26-step audit, frozen by its lock at a 2026-09-21 cicd-suite
  commit: one day before the Required Files gate stopped dying on a
  comment-only CODEOWNERS, and before upstream dropped the gates that cannot
  run on a GitHub runner (custom-tools needs pons and panic-attack). The
  audit now reports five checks: governance, hygiene, manifests, languages,
  advisory.
* `docs/wikis/` removed: an empty template scaffold whose AsciiDoc
  invariant contradicted the estate formatting gate (wiki content is `.md`).
* `Justfile` — the duplicate `guix-shell` recipe (a nix-to-guix rename
  artefact) is removed, so the Justfile parses again; `tests/e2e.sh` debt
  markers link #101.
* Workflow permissions — `main-estate-audit.yml` declares read-only
  contents; the Dependabot auto-merge job gets the `contents: write` that
  `gh pr merge --auto` needs.
