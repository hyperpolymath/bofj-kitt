= bofj-kitt — Explainme
:toc:
:icons: font

bofj-kitt is the shared Developer Environment Extension Kit for the BoJ (Box of
Justice) server. This file explains how its key infrastructure claims map to
real files. The kit's product surfaces are not built yet (see
`docs/status/ROADMAP.adoc`); what is described below is the estate governance,
session machinery and environment tooling that is genuinely present.

== Central Session Protocol Authority

Claim:
Session protocols are centrally maintained and not duplicated in this template.

How this is implemented:

* The local dispatcher (`session/dispatch.sh`) maps canonical commands to central
  protocol paths in `standards/session-management-standards`.
* Local files (`session/custom-checks.k9`, `session/local-hooks.sh`,
  `coordination.k9`) are integration-only.

Caveat:

* If `SESSION_STANDARDS_DIR` is unset and no adjacent standards checkout exists,
  the dispatcher records the command but cannot resolve central checklist paths.

== Canonical Command Surface

Claim:
Template bindings align to one canonical command model.

How this is implemented:

* `Justfile` provides thin aliases (`intake-repo`, `checkpoint-change`,
  `verify-maintenance`, `verify-substantial`, `verify-release`, `close-planned`,
  `close-urgent`, `recover-repo`, `handover-*`).
* Every alias calls `session/dispatch.sh` with canonical verb-object pairs.

Caveat:

* Recipes are wrappers only. They do not replace protocol content from
  the central standards repo.

== Runtime State Is Local

Claim:
Session state is per-repository runtime output, not standards text.

How this is implemented:

* `session/dispatch.sh` writes command and continuity-core capture stubs to
  `.session/LAST-CANONICAL-COMMAND.md` in the target repository path.

Caveat:

* Runtime files are intentionally lightweight and require human/agent completion.

== Template Token Policy

Claim:
Any remaining placeholders are inventoried, not silent.

How this is implemented:

* The CI-gated files (README, machine-readable state, `.well-known/`, etc.) have
  had their `{{TOKEN}}` placeholders filled with bofj-kitt values.
* The remaining ~75 non-CI-gated token files (`container/`, `.devcontainer/`,
  parts of `.github/`) are inventoried in
  `docs/reports/audit/repo-assessment-2026-07-16.adoc` and scheduled for
  roadmap M1.

Caveat:

* Uninitialized placeholders in the M1 backlog must not be treated as
  project-specific truth until filled.

== Environment Settings Are Rendered, Not Hand-Written

Claim:
The setup script, network allowlist and variable names for a cloud agent
session are generated from two manifests and checked for drift, so no one
maintains them by hand.

How this is implemented:

* `tools/proof-toolchain/toolchain.kyaml` says which tools the estate uses;
  `tools/environments/environments.kyaml` says which environment classes get
  them and records what each was measured to reach.
* `tools/proof-toolchain/provers.sh render` writes
  `tools/environments/rendered/agent-session/` (`setup.sh`,
  `allowed-hosts.txt`, `allowed-hosts-mcp.txt`, `env-vars.txt`).
  `render --check`, run in CI, fails when a committed file differs from what
  the manifests render, or when a file is left over that they no longer
  render.
* The script is bash, at most 100 lines of at most 200 bytes, idempotent and
  non-interactive. Every download is pinned by SHA-256 and checked before it
  is unpacked, and it never exits non-zero.
* On 2026-11-13 it was run as root against real apt: 13 items installed,
  nothing failed, and a second run reinstalled nothing
  (`tools/environments/README.adoc`).

Caveat:

* The kit renders these files; it does not apply them. The owner pastes the
  script into the cloud environment's settings and sets the allowlist.
* `kyq`, `deed` and `k9` have no pinned release, so they are reported
  `UNAVAILABLE`, not installed. Isabelle's host resets the TLS handshake
  under the Limited network.

== Honest Capability Reporting

Claim:
A session says what it has and what it lacks, and never presents a missing
tool or an unrun check as a pass.

How this is implemented:

* `tools/proof-toolchain/provers.sh doctor --json` emits one JCS-canonical
  capability record (`tools/proof-toolchain/CAPABILITY-RECORD.adoc`) with
  `PRESENT`, `DRIFT` or `UNAVAILABLE` and a reason for each tool.
* The SessionStart hook (`.claude/hooks/session-start.sh`) runs it in every
  Claude Code session, writes `.session/capability-record.json`, and prints
  `!!!` lines naming each `UNAVAILABLE` or drifted tool. It also sets up
  commit signing from `CLAUDE_SIGNING_KEY`, `CLAUDE_SIGNING_NAME` and
  `CLAUDE_SIGNING_EMAIL`.

Caveat:

* The hook always exits 0 and never installs anything, so a session with
  missing tools still starts; the `!!!` lines and the record are the signal.
* By default (`.claude/signing/mode` is `key`) the signing key is a
  long-lived secret held in an environment variable. A `cert` mode that uses
  short-lived SSH certificates is built and off by default
  (`docs/proposals/short-lived-signing-certificates.adoc`, runbook
  `docs/practice/session-signing-certificates.adoc`). Switching to it needs
  the owner's CA ceremony, which is the owner's step. Known gap: while no CA
  key is listed in `.claude/signing/trusted-cas.pub`, `cert-signing.sh
  request` exits before it makes git refuse unsigned commits, so do not
  switch the mode until that is fixed (see the roadmap).
