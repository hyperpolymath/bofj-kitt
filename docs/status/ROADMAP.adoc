= bofj-kitt Roadmap

bofj-kitt is the shared Developer Environment Extension Kit (the "SuperChainsaw")
for the BoJ (Box of Justice) server. This roadmap maps the journey from an
honest pre-alpha scaffold to a working, dogfooded kit.

== Current Status

Pre-alpha. Identity, governance, and CI are truthful and green; there is no
product code yet. See
`docs/reports/audit/repo-assessment-2026-07-16.adoc` for the assessment that
established this baseline.

== Milestones

=== M0 — Truthful baseline (this pass)
* [x] Remove the vendored affinescript subtree and uninstantiated template ABI/FFI.
* [x] Install one consistent `bofj-kitt` identity across README, manifests, and state.
* [x] Make governance CI pass its own estate rules (root-shape, no-`.md`-in-docs, banned-language, and OpenSSF-token checks).
* [x] Commit this assessment and roadmap.

=== M1 — Finish the hygiene pass
* [x] Fill the placeholder tokens that have a true value; the rest are listed as blocked in `REQUIRES_INITIALISATION.adoc` (M2/M3/owner).
* [ ] Restore a full SECURITY policy once PGP material exists (none in repo or estate canon; owner to generate a key; the root SECURITY policy carries the real contact).
* [x] Curate template-authored docs (live guidance retargeted; historical records kept; onboarding quickstarts wait on M3).
* [x] Independent conduct contact (George Booden, Open University) named in `.github/CODE_OF_CONDUCT.md`; the owner confirmed on 2026-11-13 that he agreed.
* [x] Local hooks: `install.sh`, `pre-push` and the fail-closed `scan-secrets.sh` ported from rsr-template-repo. Deferred, not done: the template's `validate-deed.sh` and canonical-validator `validate-k9.sh`. They need a matching `dogfood-gate.yml` (otherwise the K9 lane would skip silently in CI) and a decision on the shrink-only A2ML legacy ledger for the 106 `.a2ml` files (kyX, ruling D313).

=== M2 — Product spec

* [ ] Record the decisions as ADRs under `docs/decisions/`.

=== M3 — Language & scaffolding

=== M4 — First capability + tests (CRG D)
* [ ] Ship one end-to-end capability (e.g. `kitt init` provisions a compliant environment; `kitt connect` registers it with a BoJ server).
* [x] `provers.sh doctor --json`: the environment capability record (proposal E2, 2026-11-12).
* [x] `provers.sh render`: the agent-session setup script, allowlist and variable names, with a drift test in CI (proposal E3, 2026-11-12).
* [x] SessionStart hook writes the capability record to `.session/` and names UNAVAILABLE legs, never blocking (proposal E4, 2026-11-12).
* [x] E1 measured blocks for the agent session under Unrestricted (2026-11-04, 2026-11-12) and the Limited network (2026-11-13).
* [x] The setup script preinstalls what a session always needs: zstd, just, agda, coq, elan, nickel, yq, lean 4.13.0, julia 1.13.3, z3, cvc5, podman and guix (2026-11-12 to 2026-11-13).
* [x] MCP connector hosts rendered to their own allowlist, kept apart from the 20-host toolchain cap (2026-11-13).
* [x] The rendered setup script run as root against real apt: exit 0, 13 items installed, nothing failed, a second run reinstalled nothing (2026-11-13).
* [x] Short-lived signing certificates: the proposal (`docs/proposals/short-lived-signing-certificates.adoc`) and its `cert` signing mode (#120), off by default. Runbook: `docs/practice/session-signing-certificates.adoc`.
* [ ] Fix `cert-signing.sh request` (found in review of #126, verified at `cmd_request`): `write_signers` exits when `trusted-cas.pub` lists no CA key, before `configure_git` sets the fail-closed git settings, so in `cert` mode commits would not fail as the hook says. Apply those settings first, and add a test that `request` with an empty trust-anchor file leaves `git commit` failing. Latent while the mode is `key`.
* [ ] Owner: the signing-CA ceremony, then (after the fix above) switch `.claude/signing/mode` from `key` to `cert` so sessions stop using the long-lived `CLAUDE_SIGNING_KEY`.
* [ ] Owner: apply the rendered setup, allowlists and variable names to the real environment (`tools/environments/README.adoc`).
* [ ] Pin releases of kyq, deed and k9 so the setup can install them; until then they report `UNAVAILABLE`, and the Rust KYAML reader stays.
* [ ] Isabelle cannot be installed under the Limited network (its host resets the TLS handshake); decide whether to keep it on the allowlist.
* [ ] Set an elan default for the preinstalled Lean 4.13.0, so a bare `lean` works outside a project.
* [ ] Install the remaining 36 `UNAVAILABLE` tools (why3, verus, Kani, hol4 and others), each as a pinned, hash-checked download.
* [ ] Per-capability unit + integration tests; record counts in `.machine_readable/descriptiles/STATE.a2ml`.
* [ ] Replace the placeholder fuzz README with a real harness.
* [ ] Replace the generic template proofs under `verification/` with product proofs.

=== M5 — Live integration & dogfooding (CRG C → B)
* [ ] Wire live BoJ-server integration (`BOJ_SERVER_URL`, Groove manifest, mirror enablement).
* [ ] Dogfood the kit on estate repos with no known home-context failures across an evidence window (→ CRG C).
* [ ] Six genuinely diverse external environments with feedback fed back (→ CRG B).

== Future Directions

Beyond M5: a profile library for different environment classes (cloud / desktop
/ embedded) and deeper BoJ cartridge coverage. Reassessed once M2 fixes the
product's first shape.
